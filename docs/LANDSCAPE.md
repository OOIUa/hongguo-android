# 横屏分栏（暖白精修 / 内容卡片）

只影响「暖白精修」「内容卡片」「沉浸暗场」三个主题的浏览页；竖屏、播放器不走这套代码。
播放页本来就有自己的横屏全屏布局，与这里无关。

三个主题共用同一套分栏部件（`WarmPanes.kt`），只是各自页面的内容不同：暖白是整列卡片，
内容卡片是白卡 + 瀑布流，沉浸暗场是深色内容 + 少量整屏页，所以左右栏里放什么按主题分别列在下面。

## 结构

```
+------+---------------------------+---------------------------+
|      | 左列（固定可滚动）        | 右列（主内容）            |
| 导航 | 标题 / 筛选 / Tab         | 列表、网格或分区内容       |
| 栏   |                           |                           |
+------+---------------------------+---------------------------+
```

- 底部 Tab 栏在横屏时竖到左侧（`MainActivity` 里的 `AppNavigationRail`），页面内容只占剩下的宽度。
- 页面左右分栏由 `WarmTwoPane` 负责：左列永远是可滚动的 `Column`，右列由页面决定是「自己滚的列表」还是「可滚动列」（`rightScroll = true`）。
- 竖屏时不进入上述分支，页面保持原来的一整列。

## 状态栏留白

状态栏是透明浮在内容上的，所以每一列的内容都要自己让出状态栏高度，并且**这段留白要随内容滚走**，不能固定贴在页面顶部（否则页面顶部永远空一条，且返回键会被压住）。

留白不是整个状态栏高度，而是它的 `WarmTopInsetScale` 倍（当前 **0.6f**，改回 `1f` 就是完全让开状态栏）。改这一个常量，所有分栏页一起变；竖屏恒为 0，不受影响。

两种写法，全部以 `WarmPanes.kt` 为准：

| 列的结构 | 写法 |
| --- | --- |
| 整列可滚动（`Column(verticalScroll)`） | 列顶调用 `WarmTopInset()` |
| 列里是 `LazyColumn` / `LazyVerticalGrid` | 把 `LocalWarmTopInset.current` 加进列表的 `contentPadding.top` |

`LocalWarmTopInset` 只在 `WarmTwoPane` 内部有值；**在 `WarmTwoPane` 之外读到它恒为 0**。所以现在所有分栏页（包括我的账号页）都走 `WarmTwoPane`，不再有自己算状态栏的例外；`warmStatusBarTop()` 由 `WarmTwoPane` 内部调用。

## 加一个新分栏页

1. 页面里 `if (isWideLayout()) { WarmTwoPane(left = {...}, right = {...}); return }`，竖屏代码保持原样不动。
2. 左列顶部调用 `WarmTopInset()`；右列若是列表，把 `LocalWarmTopInset.current` 加进 `contentPadding.top`。
3. 测试用的 testTag 竖屏和横屏保持一致（`NavigationFlowTest` 等用例都按 tag 找控件）。
4. 竖屏回归一遍：横屏分支必须完全绕开竖屏布局。
5. 横屏分支里的区块优先复用竖屏同一批 composable（必要时把列表里的 `item {}` 抽成小 composable），不要复制一份布局。

## 沉浸暗场的页面

沉浸暗场不全是分栏：首页保留整屏竖向信息流，追剧横屏一行放 6 个；剧场、详情、我的才分栏。
三处分栏都在 `WarmTwoPane` 里传 `dividerColor = Line`——深色下不能用暖白那条
`Muted.copy(alpha = .16f)`，会发灰发白。

| 页面 | 入口 | 左栏 | 右栏 |
| --- | --- | --- | --- |
| 首页 | `ImmersiveHome` / `ImmersiveFeedPage` | 不分栏 | 整页竖向信息流；横屏底栏改成「标题一半 + 播放键 + 竖排动作」 |
| 剧场 | `ImmersiveTheater` | 剧种、筛选与排序 chip（换行）、热播榜 | 海报网格（3 列） |
| 追剧 | `ImmersiveLibrary` | 不分栏 | 整页：标题、本机/账号切换，继续看与我的追剧（横屏一行 6 个） |
| 剧集详情 | `ImmersiveDetail` | 220dp + 状态栏的头图（标题压在图上）、播放/收藏、简介、演员表、相关作品（底部） | 选集范围与剧集网格（5 列） |
| 我的 | `ImmersiveMine` | 账号卡、四个快捷入口 | 账号与隐私、设置、更新、版本说明 |

首页的横屏例外：

- 不分栏；标题、播放键和追剧/选集/详情压在画面底部：标题占页面一半，接着是播放键，
  最右是竖排的三个动作。顶部只让出状态栏本身，不再加竖屏那 6dp 额外间距和 8dp tab 内边距。
- 四个频道在横屏只用颜色和字重区分，**没有下划线**（下划线离文字太远，而且压在画面上显乱）；竖屏仍保留原来的下划线。
- 画面继续压在透明状态栏下面。顶部 180dp、底部 380dp 两条渐变按页面高度缩放：
  高度不足 520dp 时改成 32% / 58%（三个竖排动作更高），否则 380dp 会盖满整个横屏画面，
  看起来像蒙了一层黑色。
- 竖屏尺寸不变（`maxHeight >= 520.dp` 时仍是 180dp / 380dp），仍是竖排动作 + 全宽播放键。

剧集详情的横屏：头图 220dp + 状态栏高度并压着状态栏，返回键用 `statusBarsPadding`；标题和集数
压在图上，横屏用黑色 scrim（不渐隐到页面底色），标题用白色，深色/浅色主题都看得清。播放、
本机/账号收藏、简介在头图下方，相关作品在左栏底部；右栏只保留 `WarmTopInset`（0.6 倍状态栏），
不额外加顶部 padding。横屏不再挂 `DetailStatusBar`，状态栏图标跟随主题（沉浸主题本身是深色，
浅色模式下也不会出现白图标压在浅色内容上）。

云片单（`CloudLibraryContent`）自己已经分栏；追剧页的账号模式不套 `WarmTwoPane`，
和内容卡片的片单页保持一致。

## 上游 0.7.33 的页面改动怎么落位

分支已把上游 0.7.33 合进来（`git merge v0.7.33`），页面相关的三处改动在横屏里的落位：

| 改动 | 竖屏 | 横屏 |
| --- | --- | --- |
| 详情页演员表（`CastSection`） | `DetailScreen` 的 `LazyColumn`：`DetailInfo` 之后、相关作品之前 | 同一份 `CastSection` 放在左栏 `DetailInfo` 与相关作品之间，右栏选集不变 |
| 按住 2× 的顶部提示 | 播放器顶部（`statusBarsPadding` 之后 8dp） | 同一段代码，横屏贴状态栏下沿，和弹幕开关无关 |
| 账号片单元数据回填 | 数据层改动，页面自动显示真实标题/封面 | 同左 |

`CastSection` 竖屏和横屏共用一份实现（在 `DetailScreen.kt` 末尾，`internal`），三套主题的详情页都调它：
暖白/沉浸暗场直接排在简介之后，内容卡片包一层 `CardBlock` 保持白卡样式；无 cast 数据时整块不出现。
横屏左栏里它排在故事简介之后、相关作品之前，左右各留 16dp 间距，不高过左栏宽度。

## 播放器横屏的返回

播放页的横屏全屏布局不在这套分栏里，但返回行为与横屏有关：

- 系统自动旋转开着（或旋转锁定在横屏）时，横屏播放按返回直接退出播放页，回到后面的页面；
  后面的页面本身也是横屏布局，不会先翻成竖屏播放。
- 旋转锁定在竖屏时，只有「全屏观看」能把手机转成横屏播放，此时按返回先回到竖屏播放，
  再按一次才退出播放页。
- 底部控制栏的「退出全屏」按钮不受影响，始终回到竖屏播放。

判断依据是系统设置里的自动旋转开关与锁定方向；实现见 `PlayerWindowModes.kt` 的
`backReturnsToPortrait`。

## 已知未统一的地方

- **暖白片单 / 片单·红果账号**：横屏左右两列都还没有状态栏留白，第一行会贴到屏幕最上面。当时按“片单页先别动”的要求保留现状。
- **页面标题字号**：详情/榜单/播放历史用 18sp，设置/主题样式用 24sp，尚未统一。
