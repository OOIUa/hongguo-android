# 个人红果账号接入

本版在原生 APK 内提供个人账号入口。官网授权、账号设备注册、签名、登录态保存和片单请求均在设备上完成，不需要部署服务器。现有 Java 媒体链路继续负责匿名找剧与播放，账号 Cookie 不进入媒体请求或更新下载请求。

2026-10-25 本人的 0.6.2 脱敏诊断确认：App 资料已包含字符串 `biz_user_id`，网关状态为 `agw=1`，被拒原因是本地错误的数字格式限制。0.6.3 将业务账号标识按不透明字符串原样处理，并同步修正加密存储及恢复。该案例不能再归因为业务身份缺失或官网会话必然无法接入 App。实际片单与写回仍由本人核对。

## 登录与保存

1. **手机首选：官网登录。** 在独立进程打开官网桌面页面，页面加载后由用户点击“打开官网登录窗口”，再自行操作登录及平台验证。点击“完成登录”后仅提取红果官网的会话 Cookie。网页退出时清除 Cookie、网页存储与缓存。
2. **其他设备协助：扫码登录。** APK 向官网获取二维码并轮询确认；支持过期、取消和手动刷新。显示二维码不会被视作账号已登录。
3. **手机号验证码。** 使用官网明确的短信接口，每次发码及验码只提交一次。发送前持久保存重发等待时间，重启或网络超时不自动重发；遇到平台验证要求可转官网登录。
4. **高级登录态导入。** 明确区分本人官网 Cookie 和红果 App Cookie。官网来源仍需先验证官网；显式 App 来源直接验证 App 业务资料，不能强制要求 App 凭据再登录另一产品的官网。两者仍走设备注册和严格业务身份校验，非空 Cookie 不代表认证成功。不自动读取或导出官方 App 的私有文件。
5. 官网会话先按当前官网的 `has_login=true/1` 或有效公开身份字段验证，支持 `data`、`user_info`、`user` 及外层状态；不要求官网一定返回数字 UID，不把 `is_auth` 等无依据字段当作未登录。随后须通过 App 当前本人资料接口取得有效 `biz_user_id`，完成本机加密保存后才显示成功。业务账号标识不限定纯数字，保留大小写、前导零及合法符号，不转数值或使用其他字段代替；新兼容格式还要求该次资料响应的 `agw=1`。设备 ID、安装 ID、昵称和 `code=0` 均不能替代真实账号身份。
6. 官网 WebView、原生授权及后置资料请求使用一致的桌面 UA；资料请求携带官网 CSRF Cookie 对应请求头，支持默认令牌回退。官网 Cookie 与注册设备 Cookie 分开保存；只有域匹配、根路径、未过期的白名单设备 Cookie 可进入 App 请求，`install_id` 与保存的 `iid` 保持一致，设备 Cookie 不回填官网请求。
7. 登录错误区分官网会话、设备初始化和 App 账号资料校验，显示本机生成的提示、HTTP 状态或数字错误码，不显示响应原文或凭据。官网错误 13 / 1003 明确视为会话失效，403、网络或不支持的结构不冒充已登录。
8. 官网已证明登录而业务资料未通过时，只加密保存官网会话与已注册设备，状态为“官网已登录，手机云账号未接通”。重启不自动重试；用户可以直接重读资料而不重新发短信，明确过期时只清除本次重读的同一份会话。这个状态不授予云端读取、收藏写入或进度同步权限。
9. “复制诊断信息”仅在用户点击时写入剪贴板。内容是固定分类、白名单字段类型、布尔状态和限定数字网关状态，不包含 Cookie、UID/红果号、昵称、手机号、验证码、原始响应或任意服务端字段名；诊断不额外持久保存。用于区分返回结构变化与匿名回落，不能把任何单一提示或 `code=0` 当作鉴权证明。

Android Keystore AES-GCM 保护账号文件，AtomicFile 原子落盘；Android 备份保持禁用。重启后先验证已有登录态，网络错误保留本机凭据及片单并提示待验证，明确认证失效时停止同步。取消、退出及切换账号后，旧请求不得恢复会话或覆盖新账号资料。

## 本机与账户片单

- 原有本机收藏、历史及续播位置保留，登录和退出不会自动搬运或清空本机记录。
- “我的 → 红果账号与云片单”展示账户历史、账户收藏和账户预约，按账号独立保存。
- 账户历史每次读取最近 50 部，点击时按云端集号和毫秒位置续播；已读取的账号历史与收藏各最多缓存 200 部，该批次和缓存不能称为完整观看历史或完整云端备份。
- 预约区分别读取已上线、待上线各 20 部；待上线作品不可播放。
- 账户收藏接口的完整分页契约仍待验证，页面展示本次读取和缓存范围内的列表，不宣称覆盖全部收藏。
- 各列表独立处理错误，网络失败保留同一账号上次成功读取的数据；旧账号迟到结果不能进入新账号。

## 写回与同步

账户收藏与本机收藏是独立操作。详情和播放器提供“账号收藏”，提交前明确目标账号与作品；写入前读取列表，写入仅提交一次，随后回读。写请求本身被接受并不等于操作已在列表中确认。响应不确定时保留待核对状态，只允许读取核对，不自动重放收藏写入。

播放进度上报默认关闭，用户开启后仅上报此后实际播放的内容，不扫描或上传游客旧记录。播放器在真实首帧后才产生上报，携带播放请求创建时的账号代次；退出或切换账号会使旧播放器上报失效。按剧合并最新进度并加密持久保存；常规上报节流，暂停、切集及退出播放器时提交已观察到的进度。上传失败保留待发送记录，较旧的确认不得删除较新的记录。集号在 UI 使用一基，协议层使用零基模型并在请求中转换，时间始终保留毫秒。

禁止批量取消云端收藏或清空云历史；清空本机记录不触发云端删除。19 位账号、作品与分集 ID 按字符串处理。

账号身份与内容编号使用独立校验：业务账号采用本地 1024 字符资源上限，拒绝空值、占位值、空白/控制字符和无效 Unicode；这是本地存储和显示边界，不是平台格式规定。剧集、分集、设备及安装 ID 继续使用原来的数字规则。账号键原样精确比较，不作大小写或 Unicode 归一化；如果公开红果号发生变化，会要求重新验证，避免把两个账号缓存合并。
