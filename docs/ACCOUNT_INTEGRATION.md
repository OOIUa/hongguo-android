# 个人红果账号接入

本版在原生 APK 内提供个人账号功能。官网授权、账号设备注册、签名、登录态保存和片单请求均在设备上完成，不需要部署服务器。现有 Java 媒体链路继续负责匿名找剧与播放，账号 Cookie 不进入媒体请求或更新下载请求。

## 登录与保存

1. **手机首选：官网登录。** 在独立进程打开官网桌面页面，页面加载后由用户点击“打开官网登录窗口”，再自行操作登录及平台验证。点击“完成登录”后仅提取红果官网的会话 Cookie。网页退出时清除 Cookie、网页存储与缓存。
2. **其他设备协助：扫码登录。** APK 向官网获取二维码并轮询确认；支持过期、取消和手动刷新。显示二维码不会被视作账号已登录。
3. **手机号验证码。** 使用官网明确的短信接口，每次发码及验码只提交一次。发送前持久保存重发等待时间，重启或网络超时不自动重发；遇到平台验证要求可转官网登录。
4. **高级登录态导入。** 用户主动提供自己的 Cookie 后仍走设备注册和真实账号资料校验，非空 Cookie 不代表认证成功。
5. 凭据必须通过 App 账号资料接口并取得有效用户 ID，完成本机加密保存后才显示登录成功。设备身份与会话一并保存并复用。没有写入 APK 资产或日志。

Android Keystore AES-GCM 保护账号文件，AtomicFile 原子落盘；Android 备份保持禁用。重启后先验证已有登录态，网络错误保留本机凭据及片单并提示待验证，明确认证失效时停止同步。取消、退出及切换账号后，旧请求不得恢复会话或覆盖新账号资料。

## 本机与账户片单

- 原有本机收藏、历史及续播位置保留，登录和退出不会自动搬运或清空本机记录。
- “我的 → 红果账号与云片单”展示账户历史、账户收藏和账户预约，按账号独立保存。
- 账户历史每次读取最近 50 部，点击时按云端集号和毫秒位置续播；已读取的账号历史与收藏各最多缓存 200 部，该批次和缓存不能称为完整观看历史或完整云端备份。
- 预约区分别读取已上线、待上线各 20 部；待上线作品不可播放。
- 账户收藏接口的完整分页契约仍待验证，页面展示本次读取和缓存范围内的列表，不宣称覆盖全部收藏。
- 各列表独立处理错误，网络失败保留同一账号上次成功读取的数据；旧账号迟到结果不能进入新账号。

## 写回与同步

账户收藏与本机收藏是独立操作。详情和播放器提供“账号收藏”，提交前明确目标账号与作品；写入前读取列表，写入仅提交一次，随后回读。写请求本身被接受并不等于操作已在列表中确认。响应不确定时保留待核对状态，只允许读取核对，不自动重放收藏写入。

播放进度上报默认关闭，用户开启后仅上报此后实际播放的内容，不扫描或上传游客旧记录。播放器在真实首帧后才产生上报，携带播放请求创建时的账号代次；退出或切换账号会使旧播放器上报失效。按剧合并最新进度并加密持久保存；常规上报节流，暂停、切集及退出播放器时提交已观察到的进度。上传失败保留待发送记录，较旧的确认不得删除较新的记录。集号在 UI 使用一基，协议层使用零基模型并在请求中转换，时间始终保留毫秒。

禁止批量取消云端收藏或清空云历史；清空本机记录不触发云端删除。19 位账号、作品与分集 ID 按字符串处理。

## 验证范围

验证覆盖协议响应和错误、Cookie 域、写入不重放、ID 精度、设备复用、账号取消与切换、加密状态、进度队列、界面导航和原有播放回归。匿名二维码获取与匿名设备注册可作为联网探测，不能代替个人账号登录验收。

尚需本人账号完成最终验收：官网授权或短信验证、与官方 App 核对身份、收藏增删回读、历史批次、跨设备集号及秒级续播、账号退出后重新登录和上游风控场景。不得把 HTTP 200、设备注册成功、短信发送成功或离线测试通过写成个人账号登录成功。
